# Hamster_RPG

직접 만든 **C++ IOCP 서버**와 **Unity 클라이언트**로 돌아가는 2D 멀티플레이 RPG.

여러 명이 같은 월드에 접속해 서로를 보고, 움직이고, 채팅하고, 돌아다니는 몬스터를 만납니다.
캐릭터 위치·스탯·몬스터 AI는 전부 **서버가 계산**하고, 클라이언트는 받은 값을 그리기만 합니다.

| | |
|---|---|
| 클라이언트 | Unity 2022.3.62f3 (URP 2D) |
| 서버 | C++20 / Windows IOCP / Winsock2 (Visual Studio, 툴셋 v145) |
| 프로토콜 | 직접 설계한 TCP 바이너리 패킷 (`uint16 size + uint16 type + payload`) |
| 포트 | 4000 |
| 부하 테스트 | Python 3 (표준 라이브러리만) |

## 실행

### 1. 서버

`Server/Server.slnx` 를 Visual Studio 로 열고 빌드한 뒤 실행합니다.

```bash
Server\x64\Debug\Server.exe
```

콘솔에 몬스터 5마리 스폰 로그가 뜨면 접속을 받는 상태입니다.

명령줄 옵션 (둘 다 부하 테스트용, 평소엔 필요 없음):

| 옵션 | 하는 일 |
|---|---|
| `--random-spawn <범위>` | 로그인 위치를 원점 고정이 아니라 ±범위 안 랜덤으로 흩뿌림 |
| `--profile` | 5초마다 틱의 각 단계가 몇 ms 먹는지 출력 |

### 2. 클라이언트

Unity 에서 `Assets/Scenes/TitleScene.unity` 를 열고 재생합니다.
이름을 넣고 접속하면 `GameScene` 으로 넘어갑니다.

서버 주소는 `Assets/Scripts/Network/Protocol.cs` 의 `ServerIp` (기본 `127.0.0.1`) 이고,
`NetworkClient` 인스펙터에서도 덮어쓸 수 있습니다.

| 조작 | |
|---|---|
| 이동 | 방향키 / WASD |
| 공격 | 좌클릭 (마우스 방향으로 휘두름) |
| 채팅 열기 | `Enter` |
| 채팅 닫기 | `Esc` |

여러 명 테스트는 빌드된 실행 파일(`Build/Hamster_RPG.exe`)을 여러 개 켜거나
에디터 재생과 함께 띄우면 됩니다. `Application.runInBackground` 를 켜 두어서
창이 비활성화돼도 계속 동기화됩니다.

## 서버가 하는 일

### IOCP 네트워크

`AcceptEx` 로 접속을 받고, 워커 스레드를 CPU 코어 수만큼 띄워 완료 통지를 처리합니다.
TCP 는 경계가 없으므로 세션마다 수신 버퍼에 쌓아 두고 `size` 헤더만큼 모였을 때만 패킷으로 넘깁니다.
클라이언트도 같은 방식으로 조립합니다.

### 서버 권위 이동

클라이언트는 **자기 위치를 보내지 않습니다.** 누르고 있는 **방향**만 `CS_INPUT` 으로 보내고,
그것도 방향이 바뀔 때만 보냅니다(TCP 라 순서가 보장되므로 매 프레임 보낼 이유가 없음).

위치 계산은 서버의 **15Hz 고정 게임 틱**이 담당합니다. 한 틱에서 이렇게 돕니다.

```text
1. 플레이어 위치 적분 (입력 방향 × moveSpeed × dt)
2. 몬스터 AI (배회 / 순찰 / 추격 · 부활 타이머)
3. 플레이어 시야 diff → 새로 보이면 SC_SPAWN, 안 보이면 SC_DESPAWN
4. 몬스터 시야 diff
5. 락을 푼 뒤 전송 (SC_MOVEOBJECT 등)
```

내 캐릭터도 서버가 준 좌표를 따라갑니다. 클라이언트는 애니메이션만 로컬에서 돌리고,
좌표는 `LocalPlayerInterpolator` 가 다음 패킷까지 등속 보간합니다
(5유닛 이상 튀면 보간 없이 순간이동).

### 시야처리 (AOI)

전원에게 브로드캐스트하면 인원이 늘수록 트래픽이 제곱으로 늘어납니다.
그래서 월드를 격자로 나누고 **주변 3×3 섹터만** 훑습니다.

| | 값 |
|---|---|
| 월드 크기 | 4000 × 4000 (`-2000 ~ 2000`) |
| 섹터 한 칸 | 50 |
| 시야 반경 | 20 |

시야 반경이 섹터 크기보다 작아야 3×3 만 봐도 빠지는 대상이 없습니다.
플레이어마다 "지금 보고 있는 id 집합"을 들고 있다가 매 틱 비교해서, **바뀐 것만** 스폰/디스폰을 보냅니다.
몬스터는 반대로 "나를 보고 있는 사람 집합"(watchers)을 들고 그 사람들에게만 이동을 보냅니다.

### 몬스터

플레이어와 별도 맵으로 관리하되 섹터 격자에는 같이 태웁니다. id 가 `1,000,000` 이상이면 몬스터입니다.
현재 5마리가 고정 위치에 스폰되고, 행동 타입이 세 가지입니다.

| 타입 | 동작 |
|---|---|
| `Wander` | 스폰 지점 주변을 어슬렁 (1~3초마다 방향 전환, 50% 확률로 잠깐 정지) |
| `Patrol` | 스폰 지점 기준 사각 경로를 순환 |
| `Chase` | 반경 8 안에 들어온 플레이어를 추격. 거리 1까지만 붙음 |

추격은 감지(8)보다 포기(12)를 넉넉하게 잡아서 경계에서 붙었다 떨어졌다 하지 않게 했고,
집에서 12 넘게 멀어지면 추격을 접고 돌아옵니다. 죽으면 10초 뒤 집에서 부활합니다.

### 스탯과 전투

레벨업 시 `maxHp +20`, `attack +3`, `defense +1` 로 선형 증가하고
전투력은 `attack×10 + defense×6 + maxHp + level×30` 입니다. 값이 바뀌면 `SC_STAT_UPDATE` 를 보냅니다.

전투는 **서버 판정**입니다. 클라이언트는 "누구를 때리겠다"만 보내고
사거리(2.5) · 쿨타임(0.8초) · 데미지 · 사망 · 경험치는 전부 서버가 계산합니다.
몬스터 처치 시 경험치 20, 골드 10.

전투는 타겟을 찍는 방식이 아니라 **방향 공격**입니다. 좌클릭하면 클라이언트는 마우스 쪽 방향만
`CS_ATTACK` 으로 보내고, 대상은 고르지 않습니다. 서버가 그 방향을 중심으로 좌우 50도(전체 100도),
반경 2.5 의 부채꼴을 만들어 **거기 걸린 몬스터를 전부** 때립니다. 한 번 휘둘러 여러 마리가 맞을 수 있습니다.

부채꼴 판정은 주변 3×3 섹터에서 후보를 모은 뒤 내적과 `cos(50도)` 를 비교합니다. 매번 각도를 구하지 않습니다.
빗나가도 휘두른 것이므로 쿨타임은 소모됩니다.

클라이언트에도 같은 사거리·각도 값이 있지만 이건 휘두른 범위를 화면에 그리고 쿨타임 동안 패킷을
안 보내려는 것일 뿐이고, 통과시켜 보내도 서버가 다시 검사해서 버립니다.

남은 HP 가 `SC_DAMAGE` 에 함께 실려오므로 클라이언트는 체력을 직접 빼지 않습니다.
체력바와 데미지 숫자는 프리팹 없이 런타임에 만들어지고, 체력바는 처음 맞은 뒤에만 나타납니다.

## 패킷

`Server/protocol.h` 와 `Assets/Scripts/Network/Protocol.cs` 가 같은 값을 공유합니다.
**enum 값이 양쪽에 물려 있으므로 중간에 끼워넣지 말고 반드시 맨 뒤에만 추가하세요.**

### Client → Server

| 패킷 | 내용 |
|---|---|
| `CS_LOGIN` | 닉네임 |
| `CS_INPUT` | 입력 방향 `(dx, dy)` — 정규화, 정지는 `(0,0)` |
| `CS_LOGOUT` | 접속 종료 |
| `CS_CHAT` | 채팅 메시지 (UTF-8, 256바이트) |
| `CS_ATTACK` | 휘두른 방향 `(dx, dy)` — 정규화. 대상은 서버가 정한다 |

### Server → Client

| 패킷 | 내용 |
|---|---|
| `SC_LOGIN_RESULT` | 성공 여부 · 내 id · 시작 좌표 |
| `SC_SPAWN` | 시야에 들어온 엔티티 (`entityType` 으로 플레이어/몬스터 구분) |
| `SC_DESPAWN` | 시야에서 나간 엔티티 |
| `SC_MOVEOBJECT` | 엔티티 위치 |
| `SC_CHAT` | 보낸 사람 이름 + 메시지 |
| `SC_STAT_UPDATE` | 레벨 · 경험치 · HP · 공/방 · 전투력 |
| `SC_DAMAGE` | 공격자 · 대상 · 데미지 · 남은 HP |
| `SC_DEATH` | 죽은 엔티티 id. 죽음은 `SC_DESPAWN` 이 따로 오지 않는다 |

한글 채팅을 위해 문자열은 양쪽 다 UTF-8 로 처리합니다.
서버 콘솔 출력은 코드페이지에 따라 깨질 수 있지만 클라이언트끼리는 정상입니다.

## 부하 테스트

봇을 계속 밀어넣으면서 이 서버가 몇 명까지 감당하는지 눈으로 봅니다.
표준 라이브러리만 쓰므로 별도 설치가 필요 없습니다.

서버를 **랜덤 스폰 모드로** 띄웁니다. 전원이 원점에 겹치면 서로가 서로의 시야에 들어와
시야처리가 일할 여지가 없어져서, 측정값이 의미가 없어집니다.

```bash
Server\x64\Debug\Server.exe --random-spawn 25
```

같은 값을 스크립트에도 줍니다.

```bash
python Tools/loadtest.py --area 25
```

창 없이 측정만 하려면:

```bash
python Tools/loadtest.py --area 25 --no-viz
```

봇을 0.1초에 한 마리씩 넣다가 핑이 기준선보다 10ms 넘게 오르면 투입을 늦추고,
한 마리씩 넣었다 뺐다 하며 한계선 위에서 진동합니다. 그 중앙값이 감당 인원입니다.

읽을 때 주의할 점:

- **핑** — 게임 틱 대기(0~67ms)가 원래 섞여 있어 한가해도 40ms 안팎이 정상입니다. 절대값이 아니라 **기준선 대비 상승폭**으로 봅니다.
- **틱** — 15Hz 면 66.7ms 가 정상. 늘어지면 서버가 밀리는 중입니다.
- **코어** — 게임 틱이 스레드 하나라 1.0 에 붙으면 거기가 천장입니다.
- **cli** — 스크립트 자신이 밀린 정도. 25ms 를 넘으면 서버가 아니라 파이썬을 재고 있는 것이라 결과를 믿으면 안 됩니다.

`--area` 는 밀도를 정합니다. 넓게 주면 시야처리가 너무 잘 들어 서버가 놀아서 한계가 안 나옵니다.
±25 가 봇당 40명쯤으로 적당합니다.

병목을 알고 싶으면 서버에 `--profile` 을 같이 주면 틱의 어느 단계가 시간을 먹는지 5초마다 찍힙니다.
