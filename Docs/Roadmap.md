# Unity C++ 멀티플레이 서버 프로젝트 구현 현황 및 로드맵

> 기준일: 2026-06-16  
> 프로젝트 목표: C++ IOCP 서버와 Unity 클라이언트를 이용해 여러 플레이어가 같은 공간에서 접속, 이동, 채팅할 수 있는 미니 온라인 RPG 기반을 구현한다.

---

## 1. 현재까지 구현한 내용

### 1.1 서버 구조

- C++ 기반 게임 서버 구현
- Windows IOCP 기반 비동기 네트워크 구조 사용
- `AcceptEx` 기반 클라이언트 접속 처리
- `Session` 단위로 클라이언트 소켓 관리
- `Player` 단위로 접속 플레이어 정보 관리
- 패킷 구조는 `uint16 size + uint16 type + payload` 형태 사용
- 서버 포트: `4000`
- 최대 유저 수 목표: `10000`

### 1.2 서버 패킷 처리

현재 구현된 패킷 흐름은 다음과 같다.

#### Client → Server

| 패킷 | 역할 |
|---|---|
| `CS_LOGIN` | 클라이언트 로그인 요청 |
| `CS_MOVE` | 플레이어 위치 전송 |
| `CS_LOGOUT` | 로그아웃 요청 |
| `CS_CHAT` | 채팅 메시지 전송 |

#### Server → Client

| 패킷 | 역할 |
|---|---|
| `SC_LOGIN_RESULT` | 로그인 성공 여부, 내 플레이어 ID, 초기 좌표 전송 |
| `SC_SPAWN` | 다른 플레이어 생성 알림 |
| `SC_DESPAWN` | 다른 플레이어 제거 알림 |
| `SC_MOVEOBJECT` | 다른 플레이어 위치 동기화 |
| `SC_CHAT` | 전체 채팅 메시지 브로드캐스트 |

### 1.3 로그인 및 스폰

- 클라이언트 접속 후 `CS_LOGIN` 전송
- 서버는 플레이어 ID 발급
- 서버는 로그인 플레이어를 `players` 컨테이너에 등록
- 로그인 성공 시 클라이언트에게 `SC_LOGIN_RESULT` 전송
- 기존 접속자 목록을 새 클라이언트에게 `SC_SPAWN`으로 전송
- 새 플레이어 입장 정보를 기존 클라이언트에게 브로드캐스트

### 1.4 이동 동기화

- 로컬 플레이어는 Unity 클라이언트에서 직접 이동
- 로컬 플레이어의 위치 변화가 발생하면 `CS_MOVE` 전송
- 서버는 해당 플레이어의 위치를 갱신
- 서버는 `SC_MOVEOBJECT`를 다른 클라이언트들에게 브로드캐스트
- 원격 플레이어는 받은 좌표를 기준으로 보간 이동
- `Application.runInBackground = true` 설정으로 백그라운드에서도 클라이언트 업데이트가 돌도록 처리

### 1.5 Unity 클라이언트 네트워크 구조

- `NetworkClient` 싱글톤 구현
- `TcpClient` 기반 서버 접속
- 별도 수신 스레드에서 서버 패킷 수신
- TCP 스트림 특성을 고려해 `receiveBuffer`에 누적 후 패킷 단위로 조립
- Unity 오브젝트 생성/삭제/이동은 메인 스레드에서 처리하기 위해 `ConcurrentQueue<Action>` 사용
- 씬 로드 전 받은 스폰/이동 패킷은 `pendingSpawns`, `pendingMoves`로 보관 후 게임 씬 로드 시 처리

### 1.6 채팅 UI

- 800×800 해상도 기준 왼쪽 아래 채팅 UI 구현
- 기본 상태에서는 최근 채팅 1줄만 표시
- `Enter` 입력 시 채팅창 전체 열림
- 채팅 입력 중에는 이동 입력을 막을 수 있도록 `ChatUI.IsChatting()` 제공
- `Esc` 입력 시 채팅창 닫힘
- 채팅 메시지는 `Content` 아래에 `ChatMessageItem` 프리팹으로 누적 생성
- 긴 메시지 표시 시 `TMP_Text.preferredHeight` 기반으로 메시지 높이를 자동 조절
- 마우스 휠 스크롤 감도 조절 가능

### 1.7 채팅 서버 연동

- `CS_CHAT`, `SC_CHAT` 패킷 추가
- 클라이언트가 채팅 입력 후 `CS_CHAT` 전송
- 서버는 보낸 사람의 이름을 찾아 `SC_CHAT`으로 전체 브로드캐스트
- 클라이언트는 `SC_CHAT` 수신 후 `ChatUI.AddMessage()`로 채팅창에 표시
- 한글 채팅 처리를 위해 C# 클라이언트 문자열 인코딩을 UTF-8로 변경
- 서버 콘솔 출력은 깨질 수 있으나, 클라이언트 간 채팅은 정상 출력 확인

### 1.8 원격 플레이어 이름 표시

- `RemotePlayer` 프리팹 하위에 이름 표시용 Canvas 추가
- 구조:

```text
RemotePlayer
└── Canvas
    └── CharacterName
```

- `SC_SPAWN` 수신 시 서버에서 받은 닉네임을 `RemotePlayer.SetName()`으로 표시
- 로컬 플레이어 이름 표시는 현재 생략

## 2. 현재 프로젝트 상태 요약

현재 프로젝트는 다음 기능을 갖춘 상태이다.

```text
서버 접속
로그인
플레이어 스폰
위치 동기화
백그라운드 실행
채팅 UI
서버 연동 채팅
한글 채팅
원격 플레이어 이름 표시
```

따라서 현재는 “같은 공간에 여러 명이 접속해서 서로 보고, 움직이고, 채팅할 수 있는 기본 멀티플레이 구조”가 완성된 상태로 볼 수 있다.

## 3. 앞으로 구현할 내용

### 3.1 접속/퇴장 시스템 메시지

#### 목표

플레이어가 접속하거나 나갈 때 채팅창에 시스템 메시지를 표시한다.

예시:

```text
[System] pika 님이 접속했습니다.
[System] hello 님이 퇴장했습니다.
```

#### 구현 방식

- 클라이언트에서 `SC_SPAWN` 수신 시 `ChatUI.AddSystemMessage()` 호출
- 클라이언트에서 `SC_DESPAWN` 수신 시 `ChatUI.AddSystemMessage()` 호출
- 단, 처음 게임 씬 진입 시 기존 플레이어 목록을 받을 때도 접속 메시지가 과하게 뜰 수 있으므로 구분 필요

#### 추천 처리

- `isInitialSpawnFinished` 같은 플래그를 두기
- 로그인 직후 기존 플레이어 스폰은 조용히 처리
- 이후 실시간으로 들어오는 스폰만 접속 메시지 출력

---

### 3.2 플레이어 상태창 UI

#### 목표

내 캐릭터의 기본 정보를 볼 수 있는 상태창을 만든다.

표시할 정보:

- 닉네임
- 레벨
- 경험치
- HP / MaxHP
- 공격력
- 방어력
- 이동속도
- 전투력

#### 구현 방식

- Unity에 `StatusPanel` UI 추가
- `Tab`, `C`, 또는 오른쪽 버튼으로 열고 닫기
- 서버에서 받은 스탯 정보를 표시
- 초반에는 클라이언트 내부 더미 데이터로 UI만 먼저 구현 가능

---

### 3.3 캐릭터 스탯 시스템

자세한 내용은 별도 문서 `Character_Stats_Design.md`에서 설계한다.

핵심 방향:

- 스탯 계산은 서버 권한으로 처리
- 클라이언트는 표시만 담당
- 레벨업, 장비, 버프에 따라 최종 스탯 계산
- 전투력은 랭킹/표시용 수치로 사용

---

### 3.4 몬스터 스폰 및 이동

#### 목표

서버에서 몬스터를 생성하고 클라이언트에 동기화한다.

#### 패킷 예시

| 패킷 | 역할 |
|---|---|
| `SC_MONSTER_SPAWN` | 몬스터 생성 |
| `SC_MONSTER_DESPAWN` | 몬스터 제거 |
| `SC_MONSTER_MOVE` | 몬스터 위치 동기화 |
| `SC_MONSTER_HIT` | 몬스터 피격 |
| `SC_MONSTER_DEAD` | 몬스터 사망 |

#### 구현 순서

1. 서버에 `Monster` 클래스 추가
2. 서버가 일정 위치에 몬스터 생성
3. 클라이언트가 몬스터 프리팹 생성
4. 몬스터 위치와 HP 동기화
5. 사망 시 제거

---

### 3.5 공격 및 전투

#### 목표

플레이어가 몬스터를 공격할 수 있게 한다.

#### 기본 구조

- 클라이언트가 공격 입력을 서버에 전송
- 서버가 공격 가능 여부 판단
- 서버가 데미지 계산
- 서버가 몬스터 HP 갱신
- 서버가 결과를 클라이언트에 브로드캐스트

#### 패킷 예시

| 패킷 | 역할 |
|---|---|
| `CS_ATTACK` | 공격 요청 |
| `SC_ATTACK_RESULT` | 공격 결과 |
| `SC_DAMAGE_TEXT` | 데미지 숫자 표시 |

#### 추천 방향

- 클라이언트가 데미지를 직접 계산하지 않기
- 서버에서 거리, 쿨타임, 대상 유효성 검사
- 클라이언트는 이펙트와 UI 표시만 담당

---

### 3.6 경험치 및 레벨업

#### 목표

몬스터 처치 시 경험치를 얻고 레벨업한다.

#### 구현 방식

- 서버 `Player`에 `level`, `exp`, `requiredExp` 추가
- 몬스터 사망 시 기여 플레이어에게 경험치 지급
- 경험치가 요구량 이상이면 레벨업 처리
- 레벨업 시 MaxHP, 공격력 등 기본 스탯 증가
- `SC_STAT_UPDATE` 패킷으로 클라이언트 UI 갱신

---

### 3.7 아이템 및 인벤토리

#### 목표

몬스터 처치 후 아이템 획득, 인벤토리 표시를 구현한다.

#### 구현 순서

1. `ItemData` 구조 정의
2. 서버에 플레이어 인벤토리 추가
3. 아이템 획득 패킷 추가
4. Unity 인벤토리 UI 구현
5. 장비 착용 기능 추가
6. 장비 스탯이 캐릭터 스탯에 반영되도록 처리

---

### 3.8 장비 강화

#### 목표

기본 무기 강화 시스템을 구현한다.

#### 추천 규칙

- 시작 무기: `낡은 검`
- 기본 공격력: `+3`
- 강화 성공 시 공격력 `+3`
- 강화 비용: `50 × 2^현재강화수치`
- 성공률: `max(10%, 100% - 현재강화수치 × 10%)`
- 실패 시 골드만 소모

#### 구현 방향

- 강화 성공/실패 판정은 서버에서 처리
- 클라이언트는 강화 요청과 결과 표시만 담당
- 강화 결과는 `SC_EQUIPMENT_UPDATE`, `SC_STAT_UPDATE`로 반영

---

### 3.9 랭킹

#### 목표

전투력을 기준으로 플레이어 랭킹을 표시한다.

#### 구현 방향

- 서버에서 접속 중 플레이어의 전투력 계산
- `CS_RANKING_REQUEST` 요청 시 상위 N명 반환
- 나중에 DB 연동 시 전체 유저 랭킹으로 확장

---

### 3.10 DB 연동

#### 목표

계정, 캐릭터, 스탯, 인벤토리 데이터를 저장한다.

#### 추천 저장 대상

- 계정 ID
- 캐릭터 이름
- 레벨
- 경험치
- 골드
- 현재 위치
- 장비 정보
- 인벤토리
- 강화 수치

#### 구현 방향

- 처음에는 SQLite 또는 MySQL 중 하나 선택
- 서버 메인 네트워크 스레드에서 직접 DB 접근하지 않기
- DB 작업 큐를 따로 두고 비동기 처리

## 4. 추천 개발 순서

현재 상태에서 가장 자연스러운 다음 순서는 다음과 같다.

```text
1. 접속/퇴장 시스템 메시지
2. 상태창 UI
3. 서버 PlayerStats 추가
4. SC_STAT_UPDATE 패킷 추가
5. 몬스터 스폰
6. 공격 요청 및 데미지 처리
7. 경험치/레벨업
8. 아이템/장비
9. 강화
10. 랭킹
11. DB 저장
```

가장 먼저 할 작업은 `상태창 UI + 서버 PlayerStats`를 추천한다.  
이유는 이후 전투, 아이템, 강화, 랭킹이 모두 캐릭터 스탯을 기반으로 하기 때문이다.

## 5. 포트폴리오 관점에서 강조할 수 있는 점

이 프로젝트는 단순 Unity 게임이 아니라, 직접 구현한 C++ 서버와 Unity 클라이언트가 통신하는 구조라는 점이 중요하다.

포트폴리오에서 강조할 포인트:

- C++ IOCP 기반 비동기 서버 구현
- 패킷 프로토콜 직접 설계
- TCP 스트림 패킷 조립 처리
- 서버 권한 기반 이동/채팅 구조
- Unity 메인 스레드와 네트워크 수신 스레드 분리
- 멀티 클라이언트 스폰/이동/채팅 동기화
- 한글 채팅을 위한 UTF-8 패킷 처리
- 이후 전투/스탯/DB 확장 가능한 구조
