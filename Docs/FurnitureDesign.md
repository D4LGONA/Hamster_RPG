# 건축(가구) 시스템 설계안

> 기준일: 2026-09-25  
> 상태: **설계안. 아직 구현 안 함.**  
> 전제: 하우징([ServerFileMap.md](ServerFileMap.md)의 `GameServer_House.cpp`)이 이미 있다.
> 집은 월드에 설치되고, 집 안은 `zoneId`(= houseId)로 구분되는 별도 공간이다.

---

## 1. 무엇을 만드는가

집 **안**에 가구를 놓고, 치우고, 옮기는 기능.

- 가구는 **집 안에서만** 존재한다. 월드에는 안 나간다.
- 집 안은 ±4.5 크기(`HOUSE_INTERIOR_HALF_X/Y`)의 작은 방이다.
- 지금 하우징이 그렇듯 **서버가 전부 검증**한다. 클라는 요청만 하고 결과를 받는다.

---

## 2. 데이터 구조

### 2.1 Furniture (새 파일 `Furniture.h`)

| 필드 | 설명 |
|---|---|
| `id` | 가구 고유 id |
| `houseId` | 어느 집에 있는지 (= zoneId) |
| `itemType` | 가구 종류 (침대/책상/화분…). 클라가 프리팹을 고르는 값 |
| `x`, `y` | 집 안 좌표 |
| `rotation` | 0/90/180/270 네 방향만 (`std::uint8_t` 0~3) |

`watchers`는 **없다.** 집 안은 좁아서 AOI를 안 쓰고, 같은 집에 있는 사람 전원에게 보낸다(4.3).

### 2.2 보관 위치

```cpp
// GameServer, playersLock으로 보호 (players/monsters/houses와 같은 락)
std::unordered_map<std::uint32_t, Furniture> furnitures;              // id -> 가구
std::unordered_map<std::uint32_t, std::vector<std::uint32_t>> houseFurnitures;  // houseId -> 가구 id들
```

두 번째 map은 "이 집 가구 전부"를 빨리 찾기 위한 것이다. 집에 들어갈 때 목록을 통째로 보내야 하고,
충돌 검사도 같은 집 안에서만 하면 되므로 매번 전체를 훑지 않는다.

### 2.3 id 대역

지금 대역은 이렇다.

```text
1 ~ 999,999          플레이어
1,000,000 ~ 1,999,999  집       (HOUSE_ID_BASE)
2,000,000 ~            몬스터   (MONSTER_ID_BASE, 위가 열려 있음)
```

가구는 `FURNITURE_ID_BASE = 3,000,000`으로 새 대역을 준다.
이때 `IsMonsterId`가 지금 `id >= MONSTER_ID_BASE`라서 가구 id까지 몬스터로 판정한다.
**`id >= MONSTER_ID_BASE && id < FURNITURE_ID_BASE`로 고쳐야 한다.** (놓치기 쉬운 지점)

## 3. 패킷 3종 + 응답

`PACKET_TYPE`은 클라(`Protocol.cs`)와 값이 물려 있으므로 **맨 뒤에만** 추가한다.

### 3.1 클라 → 서버

| 패킷 | 필드 | 설명 |
|---|---|---|
| `CS_FURNITURE_PLACE` | `itemType`, `x`, `y`, `rotation` | 설치 |
| `CS_FURNITURE_REMOVE` | `furnitureId` | 삭제 |
| `CS_FURNITURE_MOVE` | `furnitureId`, `x`, `y`, `rotation` | 이동(회전 포함) |

houseId는 **안 받는다.** 서버가 그 플레이어의 `zoneId`를 보면 알 수 있고,
클라가 보낸 값을 믿으면 남의 집에 설치하는 요청을 막을 수 없다.

### 3.2 서버 → 클라

| 패킷 | 필드 | 언제 |
|---|---|---|
| `SC_FURNITURE_SPAWN` | `furnitureId`, `itemType`, `x`, `y`, `rotation` | 설치 성공 / 집에 들어와서 목록 받을 때 |
| `SC_FURNITURE_MOVED` | `furnitureId`, `x`, `y`, `rotation` | 이동 성공 |
| `SC_FURNITURE_REMOVED` | `furnitureId` | 삭제 성공 |
| `SC_FURNITURE_RESULT` | `success`, `reason` | 실패했을 때 요청자에게만 |

`SC_HOUSE_RESULT`처럼 `reason` 코드를 쓴다.

```text
0 성공
1 집 안이 아님 / 존이 안 맞음
2 내 집이 아님 (권한 없음)
3 방 밖으로 나감 (좌표 범위)
4 다른 가구와 겹침
5 출입구를 막음
6 개수 한도 초과
7 알 수 없는 가구 종류
8 그런 가구 없음 (id 오류)
```

성공했을 때 `RESULT`를 따로 보내지 않고 `SPAWN`/`MOVED`/`REMOVED`가 곧 성공 신호다.
(패킷 수를 줄이려는 것. 클라가 "요청 보냄 → 응답 대기" 상태를 만들 거면 성공 RESULT도 보내는 게 편하다. → 결정 필요)

## 4. 서버 검증 규칙

요청이 오면 **이 순서대로** 본다. 앞에서 걸리면 뒤는 안 본다.

### 4.1 권한

1. 플레이어가 존재하는가
2. `player.GetZoneId() != 0` 인가 (집 안에 있는가) → 아니면 reason 1
3. 그 집이 `houses`에 있는가
4. `house.GetOwnerName() == player.GetName()` 인가 → 아니면 reason 2

즉 **자기 집 안에 들어가 있을 때만** 가구를 건드릴 수 있다. 남의 집에 놀러 가서는 구경만 한다.
소유권을 이름으로 거는 건 지금 하우징과 같은 이유다(DB가 없어 playerId가 재접속마다 바뀜).

삭제·이동은 추가로 **그 가구가 이 집 것인지**(`furniture.houseId == player.zoneId`) 확인한다.
id만 바꿔 보내서 남의 집 가구를 지우는 걸 막는다.

### 4.2 좌표

- `|x| <= HOUSE_INTERIOR_HALF_X - 가구 반지름`, `|y|`도 같은 식 → 벽을 뚫고 나가지 않게
- `NaN`/`무한대` 체크 (클라가 이상한 float을 보낼 수 있다)
- 가구 크기는 `itemType`별 표(`FURNITURE_SIZE[]`)로 서버가 가지고 있는다. 클라가 보낸 크기를 믿지 않는다

### 4.3 충돌

- 같은 집 가구들과 **AABB**(축 정렬 사각형)로 겹치는지 검사. 회전은 0/90/180/270뿐이라
  90/270이면 가로·세로만 바꾸면 된다. 그래서 회전이 섞여도 AABB로 충분하다.
- **출입구 보호**: 들어왔을 때 서는 자리(`HOUSE_ENTRY_Y = -3.0`) 주변 일정 반경에는 못 놓는다.
  안 막으면 자기 집에 들어가자마자 가구에 끼어서 못 움직이는 상황이 생긴다.
- 사람과의 충돌은 **검사하지 않는다.** 가구 위에 서 있어도 되게 둔다(지금 월드도 플레이어끼리 안 막는다).

### 4.4 한도

- 집 하나당 가구 **30개**로 시작. `MAX_FURNITURE_PER_HOUSE` 상수.
- 연타 방지: 같은 플레이어의 가구 요청은 **0.2초에 한 번**만 받는다(`Player`에 마지막 요청 시각).
  안 넣으면 봇이 설치/삭제를 무한 반복해서 브로드캐스트를 유발할 수 있다.

## 5. 브로드캐스트 범위

집 안은 ±4.5짜리 방이라 **AOI를 쓰지 않는다.** 시야 계산 없이 같은 집에 있는 사람 전원에게 보낸다.

| 상황 | 받는 사람 |
|---|---|
| 설치/이동/삭제 성공 | `zoneId == houseId`인 플레이어 전원 (요청자 포함) |
| 집에 들어옴 | 그 사람에게만 `SC_ZONE_CHANGE` 뒤에 가구 목록 전부 |
| 집에서 나감 | 아무것도 안 보냄 (클라가 집 씬을 버림) |
| 월드에 있는 사람 | **안 보냄.** 가구는 월드에 존재하지 않는다 |

`zoneId`로 사람을 찾으려면 지금은 `players`를 전부 훑어야 한다. 한 집에 몇 명 안 들어가니
당장은 괜찮지만, 신경 쓰이면 `zoneId -> playerId 집합` map을 하나 두면 된다. (→ 결정 필요)

집에 들어갈 때 가구가 30개면 패킷이 30개 나간다. 지금 구조(패킷 하나 = 가구 하나)로 시작하고,
느려지면 여러 개를 한 패킷에 담는 묶음 패킷으로 바꾼다.

## 6. 나중에 DB에 저장해야 할 값 (스키마 초안)

지금은 전부 메모리라 서버를 끄면 집도 가구도 사라진다. DB를 붙이면 이 표가 그대로 테이블이 된다.

### `house`

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `house_id` | BIGINT PK | 지금의 id 대역은 메모리용. DB에서는 자동 증가 |
| `owner_account_id` | BIGINT | **지금은 이름(`ownerName`)으로 걸고 있다.** 계정이 생기면 계정 id로 바꾼다 |
| `world_x`, `world_y` | FLOAT | 월드 설치 위치 |
| `created_at` | DATETIME | |

### `furniture`

| 컬럼 | 타입 | 비고 |
|---|---|---|
| `furniture_id` | BIGINT PK | |
| `house_id` | BIGINT FK | 인덱스 필요 (집 들어갈 때 이걸로 조회) |
| `item_type` | INT | 가구 종류 |
| `x`, `y` | FLOAT | 집 안 좌표 |
| `rotation` | TINYINT | 0~3 |

### 나중에 필요해질 것

- `player_inventory`: 지금은 아무 가구나 무한으로 놓을 수 있다. 인벤토리/재화가 생기면
  설치할 때 소모하고 철거할 때 돌려주는 규칙이 붙는다. (`item_type`, `count`)
- `house_visit_permission`: 남의 집 출입 허용 여부. 지금은 아무나 들어갈 수 있다.

**저장 시점**은 매 변경마다 쓰지 말고, 변경된 집을 표시해 뒀다가 주기적으로(예: 30초) 몰아서 쓰는 방식을 권한다.
가구 이동은 드래그로 연달아 올 수 있어서 매번 쓰면 DB가 부담된다.

## 7. 구현 순서 제안

1. `Furniture.h` + `GameServer`에 map 2개, id 대역(`IsMonsterId` 수정 포함)
2. 패킷 정의(`protocol.h` + 클라 `Protocol.cs`) — 값은 맨 뒤에 추가
3. 설치(`CS_FURNITURE_PLACE`) + 집 입장 시 목록 전송 → **여기까지 되면 눈에 보인다**
4. 삭제, 이동
5. 한도/연타 방지
6. 클라 UI(가구 고르기, 배치 미리보기)

## 8. 결정 사항 (2026-09-25 확정)

| 항목 | 결정 | 이유 |
|---|---|---|
| 성공 RESULT 패킷 | **안 보낸다.** `SPAWN`/`MOVED`/`REMOVED`가 곧 성공 신호 | 패킷이 줄고, 어차피 같은 정보다. 클라는 "요청 후 응답 대기"가 아니라 "서버가 보내 준 대로 그린다"로 만든다. 실패했을 때만 `RESULT`가 온다 |
| `zoneId -> 플레이어` map | **안 만든다.** `players` 전체 순회로 시작 | 한 집에 들어가는 인원이 적고, 부하 테스트에서 락 경합이 0.01ms였다. 최적화는 느려진 뒤에. → [LoadTest-2026-09-25.md](LoadTest-2026-09-25.md) |
| 가구 종류 | **5종으로 시작**: 침대 / 책상 / 의자 / 화분 / 러그 | 크기가 서로 달라서(큰 것·작은 것·바닥에 까는 것) 충돌 검사와 좌표 검증을 제대로 시험할 수 있다. 러그는 바닥 장식이라 나중에 "겹쳐 놓을 수 있는 가구" 규칙이 필요한지도 드러난다 |
| 회전 | **4방향(0/90/180/270)** | AABB 충돌로 충분해진다. 자유 회전은 OBB 충돌이 필요해서 지금 단계에 비해 비싸다 |

가구 종류는 서버가 크기 표를 갖는다(4.2). 클라 프리팹 5개가 필요하다.

```cpp
// 가로, 세로 (집 안 좌표 기준)
FURNITURE_SIZE[] = {
    {2.0f, 1.2f},   // 0 침대
    {1.6f, 0.8f},   // 1 책상
    {0.7f, 0.7f},   // 2 의자
    {0.6f, 0.6f},   // 3 화분
    {2.0f, 1.5f},   // 4 러그
};
```

숫자는 시작값이다. 방이 ±4.5(가로세로 9)이므로 침대가 방의 약 1/4 폭을 차지한다.
